# 潮窗字段与双向通行

id保持字符串。kind取tide、ship、pilot、block。start/end带时区；统一UTC秒。tide的value为潮高；ship为吃水；m/cm统一为m。ship的aux为通航分钟。version为递增版本，采用同ID最高版；同版多条隔离。潮位乱序按时间排序。

## direction（可选列）

`direction` 是可选第9列，缺列或留空按上行处理，旧8列计划可直接运行。

- 取值：`up`/`上行`/`进港`/`in`；`down`/`下行`/`出港`/`out`。大小写、全角不敏感。
- 只对 `ship` 生效；其他类型忽略该列。
- 其他写法整行隔离，原因 `DIRECTION`，不影响其余记录。

业务含义：上行船在口外锚地待泊；下行船在内港，申请开始即离泊，最早离泊的那艘按 `start` 判为已在窄段内。

## 潮窗与占用

基准水深8m，安全余量1m，要求潮高>=吃水+1-8。相邻潮位最长允许3小时插值；缺口不外推。航道区间为半开，结束同刻可开始下一航次。引航窗口须覆盖整个航次。

冲突潮位时刻保留为插值断点，相邻有效观测不能跨越该时刻推算安全窗。同一UTC时刻的潮位不同值全部隔离为TIDE_TIME_CONFLICT，不能用其中任意值开启安全窗；同值重复仅保留编号最小者。

## 双向通行序列（M5）

单向窄段同一时刻只允许一个方向占用。排程以方向编队为单位，不在窄段内会船：

- **选向**：按各方向最紧迫的最晚放行时刻（潮窗与引航窗口求交、扣除航次时长）比较，紧迫一方先走。
- **编队**：同向船首尾相接连续放行，中间不留空档；空档留给对向换向。
- **换向**：异向之间必须有清空等待 `CHANGEOVER_SECONDS`（默认900秒，可用同名环境变量调整）。清空等待本身占用航道，登记为 `CHANGEOVER` 占班，并在工作台“换向准备”列出四步：确认本向全部驶出、瞭望复核无对向船、引航员换乘与系缆检查、发布对向放行许可。
- **已进段优先**：开排时已在窄段内的下行船以最早申请时刻识别，必须先清空，不能被赶潮上行船扣在段内。
- **等待位置**：未进窄段的上行船在“下游待泊锚地”、下行船在“上游待泊锚地”等待；同批后续船在“窄段入口编队位”排队；只有确已进段的船才记“窄段内待避区”。
- **代价**：编队边界做有界搜索，按（失约船数, 进段船扣停秒, 总等待秒, 换向次数, 编队数）字典序取小，节点预算固定，结果确定。

无法满足的船不静默丢弃：无潮窗记 `NO_SAFE_WINDOW`，被前序挤掉记 `WINDOW_MISSED`，工作台显示“无安全窗/潮窗失约”，整批进入阻断待复核。

## 同一段只有一方向

M6 把航道占用条按时间切分，逐段核对方向唯一性，`lane_spans` 给出每段方向与是否独占；出现异向重叠记 `lane_conflicts`，工作台“换向冲突”非零即阻断。

## 恢复与占班

批次以规则版本与输入摘要为键，重复执行同一内容复用同一批次。排程的航道占班按（类型, 方向, 起, 止, 船舶）确定槽位写入 `occupancy`，重跑只补不重复。

`POST /api/restore` 回放指定旧修订的排程序列（不重算），占班按同一槽位幂等同步，因此中断后多次恢复不会重复生成等待占班。
